1. Concurrency: sequential only. `oz_do.do()` loops `while blocker is None:` (oz_do.py:476) calling `worker.run_once()` synchronously (oz_do.py:517); the adapter blocks on `proc.communicate` (oz_worker.py:81) or `proc.wait` (oz_worker.py:130). `oz_flow._execute` runs one stage or host node at a time (oz_flow.py:711-717). The inbox supports concurrent claimers (leases, transactional `claim_prepared`, oz_runtime.py:362-409; concurrency test tests/test_oz_planner.py:223) but nothing drives multiple workers in parallel. `oz_manual.run` holds an exclusive per-flow lock (oz_manual.py:99, 326).

3. Streaming: no. `examples/claude_cli_adapter.py:56-62` uses `--output-format json` and parses after exit; no `stream-json` anywhere.

Requires the selective profile.

6. DAG: `oz_flow.admit` (oz_flow.py:132) validates up to 256 nodes with `in`/`after` edges; per-node commits as checkpoints (oz_flow.py:353); resume by rerun; stale sources via `bump_source` (oz_flow.py:303) / `oz_manual.revise`. Failed nodes block the flow.
7. Integration surface: `oz` CLI (oz_cli.py:28); Python `oz_do.do(request, workspace=..., adapter=...)` (oz_do.py:409) needs an explicit adapter; flat py-modules, not a package. No MCP server.
8. Model-produced reusable rule executed later without a model: not found. Checks come from the request and map to host-registered verifiers (oz_accept.py:140); oz_flow states model output never selects an operation, check, destination or budget (oz_flow.py:5-7).
