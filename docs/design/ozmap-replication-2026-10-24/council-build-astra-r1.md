# Council build review: OZ map clean replication, round 1

I do not sign this build. The supplied diff implements the main allocation formulas, arithmetic predicates, and numerical thresholds, but several integration paths can lose authentication reconciliation, certify isolation without sufficient evidence, or report magnitude despite invalid prerequisites. The reported passing tests do not cover these paths. This is a static review of the supplied redacted pack; I did not inspect excluded operation content, rerun tests, or make evaluation calls. All ten implementation interpretations are addressed below.

1. BLOCKER A4.2, `run.py:telemetry`, `isolation.py:telemetry_checks`. The telemetry certificate overstates its evidence. `sandbox_clean_home` is inferred from a directory listing before CLI startup and a plain event stream. That does not establish the sandbox’s effective instruction state after startup generates bundled skills. Likewise, contrasting `login status` outputs establishes that command’s behavior, without proving the execution route’s credential source. **Fix:** require evidence tied to the pinned execution path establishing authentication file access and effective instruction sources, using metadata without token contents. Do not certify either property from the current booleans alone. **Test:** inject a startup instruction source or an alternative credential lookup while preserving the initial listing and plain reply; certification must fail.

2. BLOCKER A4.2 and A4.5, `run.py:CellRun.run`, `record_features`, `Slots`, `CellRun.budget`. The Codex cell lock is acquired after recovery, budget reconstruction, and the feature probe. `record_features()` reconstructs worker 0 without acquiring its slot. A second process can therefore erase an active worker’s home, recover another process’s live markers, or retain stale budget and launch prerequisites while waiting. Sonnet has no equivalent cell serialization. **Fix:** acquire the applicable experiment and cell guards before inspecting mutable state, repeat prerequisites after waiting, and require slot ownership for every worker operation. Make budget reservation atomic across processes. **Test:** run competing cells with barriers; assert no active home is rebuilt, no live marker is recovered, and neither allocation nor backend caps can be exceeded.

3. BLOCKER A4.2 and A4.11, `run.py:recover_inflight`, `after_group`, `reconcile`. Recovery records an interrupted attempt and deletes its marker without establishing that the child has ended or reconciling its authentication. There is also a crash window after attempts and marker removal but before reconciliation. The next reconstruction can destroy a refreshed token and reuse the obsolete baseline. **Fix:** persist child identity, baseline generation, and pending reconciliation state. Establish termination, inventory every affected worker, and reconcile before any reconstruction or launch. Ambiguous recovery must stop Codex. **Test:** terminate the runner during execution and immediately before reconciliation, including a worker refresh; resume must preserve authentication evidence and never launch from an unreconciled baseline.

4. BLOCKER A4.2 and A4.5, `run.py:telemetry`. Telemetry bypasses the normal durable launch lifecycle. It lacks an in flight marker, experiment serialization, slot reservation, full freeze verification, baseline inventory verification, and the persistent Codex stop check. It propagates changed authentication even when the call reported authentication failure. A propagation exception merely prints a message and can leave a successful telemetry certificate. **Fix:** route telemetry through the same durable reservation, isolation, capture, reconciliation, and stop machinery as evaluation, retaining its separate allocation. Publish successful certification only after reconciliation succeeds. **Test:** crash each telemetry phase, inject authentication failure with changed credentials, and force propagation failure; calls must remain charged and subsequent evaluation must remain blocked.

5. BLOCKER A4.2, `run.py:judge_codex`, `after_group`, `isolation.py:Isolation.propagate`. Authentication failure detection depends on the selected outcome. Timeout and tool verdict branches return before authentication detection, and the regex misses the pack’s observed `401 Missing bearer` message. Propagation also lacks an expected baseline hash comparison, so an intervening reseed is not reliably protected by `last_refresh` alone. **Fix:** detect authentication failure independently of answer, event, and timeout outcomes. Propagate only against the recorded baseline generation under the lock; reject stale or ambiguous provenance. **Test:** cover authentication failure combined with timeout, uncertain events, unchanged credentials, and changed credentials, plus an intervening owner reseed. Every ambiguous case must stop Codex without replacing the newer baseline.

6. BLOCKER A4.2, `run.py:after_group`, `telemetry`. The claim that token text never leaves baseline and worker homes is not enforced. Both paths write arbitrary stdout and stderr to captures. A child that emits an authentication token therefore writes it outside the permitted locations, even if its tool event subsequently invalidates efficiency. **Fix:** sanitize secret material before persisting captures, diagnostics, parsed results, or event fields. Preserve necessary hashes and a redaction record without persisting the secret, and invalidate evidence involving credential disclosure. **Test:** have a controlled child emit unique authentication sentinels through stdout, stderr, and error fields; no artifact outside the permitted homes may contain them.

7. BLOCKER A4.2 and A4.7, `run.py:Executables`, `prepare_call`, `verify_freeze`, `isolation.py:instruction_sources`. Per call executable verification compares a cached hash computed at runner initialization. It does not hash the executable immediately before later launches. Freeze verification checks the frozen version against the pinned version but does not compare the newly observed version to that pin. Instruction discovery also suppresses filesystem errors. **Fix:** verify the actual executable and any launcher payload before every spawn, check the current version, validate environment values that select executable or configuration sources, and fail closed when instruction discovery is unreadable. **Test:** replace the executable between groups, change a launcher payload without changing its wrapper, and deny access to an ancestor instruction location; all must prevent launch.

8. BLOCKER A4.2 and A4.3, `cli-flags.json:unsupported`, `run.py:cli_flags`. `code_mode_host` is recorded as unsupported despite the notes explicitly saying its disable option is accepted and disables it. Omitting an available disable option to avoid an inconvenient error event does not implement A4.2. **Fix:** disable it, or obtain a prospective signed exception defining the permitted feature state and treatment of the resulting notice. Do not silently broaden the notice exception. **Test:** every supported required disable option must appear in the frozen argv unless a specific signed exception authorizes its omission.

9. BLOCKER A4.1 and A4.5, `run.py:Options`, `CellRun.run`, `main`, `score.py:score_run`. Run identity and mode are not immutable. Fake bootstrap results can satisfy live dependencies, and a resumed cell can combine fake and live attempts. Choosing another run directory also creates independent budget and slot accounting for the same replication. **Fix:** bind an immutable experiment identity, execution mode, freeze identity, baseline lineage, and authoritative budget ledger before the first attempt. Reject mixed modes and prevent another directory from resetting the experiment’s allowances. Reports must explicitly distinguish simulation from evaluation. **Test:** attempt live continuation from fake bootstrap, change mode during resume, and start a second directory for the same experiment; each must fail before dispatch.

10. BLOCKER A4.1 and A4.8, `run.py:freeze_record`, `verify_freeze`, `main`, `score.py:_evidence_ok`, `score_run`. Freeze can be overwritten after attempts, and scoring uses current code, classification, workload, and oracle without checking them against a run bound freeze. The provenance audit checks prompt hashes and a launch record’s `problems` field, but does not verify captured output hashes or establish that reported answers and usage derive from those captures. The new harness tests are also absent from the freeze globs. **Fix:** bind and preserve the authorized freeze with the run, reject replacement after dispatch, freeze all relevant executable checks, and verify the artifact chain before permitting claims. **Test:** change a frozen input, capture, launch identity, answer record, or admission record; scoring must detect the mismatch and withhold affected claims.

11. BLOCKER A4.3, `events.py:classify_stream`. Execution evidence is overwritten by the last event for an item. A completed execution followed by a declined update can become a refused request. Missing item identifiers can also collapse distinct events. Interpretation 3 is rejected: every top level `error` is currently exempted without examining whether it falls within the signed exception. **Fix:** accumulate execution evidence monotonically, treat ambiguous item identity conservatively, and remove the unrestricted top level error exemption. Any additional transport exception needs explicit protocol authority. **Test:** execution followed by decline, duplicate or missing identifiers, and an unknown top level error must never become plain or merely refused.

12. OK A4.3, `events.py:_present`, `_tool_verdict`. Interpretation 2 is acceptable as a representation rule: `exit_code: null` and an empty output string do not themselves demonstrate execution, while numeric exit code zero does. This does not authorize discarding earlier execution evidence or inferring interception from an incomplete stream. Item 11 requires those protections.

13. BLOCKER A4.3 and A4.5, `run.py:judge_codex`, `judge_sonnet`, `run_batches`. Timeout takes precedence over tool classification, permitting an executed or refused call to become retryable infrastructure failure. Sonnet timeout handling discards available output before classification. Nonzero exit can also make an otherwise delivered reply retryable. **Fix:** preserve terminal event and answer evidence before deciding retry eligibility. Retry only failures satisfying the frozen infrastructure predicate, never a terminal refusal, execution, uncertainty, or answer repair. **Test:** combine timeout or nonzero exit with execution evidence, refusal, and a complete answer; no prohibited second model call may occur.

14. BLOCKER A4.10 and A4.11, `score.py:_groups_makespan`, `cell_summary`. Interpretation 1 is rejected as the gating makespan definition. Summing maximum child durations omits launch skew and the harness’s own preparation, parsing, admission, rule execution, audit handling, and delivery time. These omissions differ between arms and can manufacture a timing pass. Excluding unrelated process waiting does not justify excluding experimental work. **Fix:** freeze and measure actual submission to resolution timing, including the applicable bootstrap and local work. Report the existing statistic separately as child execution time if useful. **Test:** introduce controlled local processing and launch delays while keeping child durations constant; the gate’s makespan must reflect those delays.

15. BLOCKER A4.6, A4.10, and A4.11, `run.py:interpret`, `run_bootstrap`, `_run_locked`, `score.py:score_run`. Interpretation 8 is rejected. A parsed bootstrap envelope with rejected OZ answers retains outcome and status `ok`, so `completion_failure` remains false. More generally, `_run_locked()` writes `DONE.json` and returns zero for terminal unsuccessful outcomes unless the budget exhausted or interruption flag was set. Terminal disposition is not successful completion. **Fix:** record malformed or missing bootstrap answers as completion failure, retain proposed rules only as recorded observations, and separate settled attempts from complete cells. Do not resend terminal outcomes. **Test:** provide a valid envelope with malformed answers and valid rule proposals, plus refused ordinary batches; required comparisons must remain inconclusive and incomplete cells must not return successful completion.

16. BLOCKER A4.1 and A4.6, `bootstrap.py:load_R`, `run.py:CellRun.gates`, `score.py:score_run`. Classification validation is deferred until scoring, does not require entries for every operation, and converts a classification error into `R=[]` without adding a validity failure. An invalid classification can therefore be treated like a legitimate empty rule shaped subset. **Fix:** validate the complete classification before learner dispatch and bind it to the freeze. Preserve a distinction between valid empty R and invalid classification. **Test:** omit an operation, use an invalid field or timestamp, or alter the classification hash; launch must stop and scoring must not permit claims from the defective classification.

17. BLOCKER A4.4, A4.10, and A4.11, `run.py:run_BC`, `score.py:cell_summary`. Interpretation 7 is not acceptable as implemented. An unanswered audit can coexist with a complete cell because the rule supplies the corresponding workload answer and audit completion never reaches the scoring prerequisites. Preventing warm reuse does not make the current wave’s required audit complete. **Fix:** represent unresolved required audits explicitly and make affected comparisons inconclusive. Preserve the outcome without an unauthorized repair call. **Test:** return no audit answer while providing complete usage and otherwise correct rule answers; the affected cold comparison must not pass.

18. BLOCKER A4.10 and A4.11, `gates.py:magnitude`, `pooling_gate`, `boolq_gate`, `run.py:CellRun.gates`. `magnitude()` can return direction replication and the pilot magnitude label despite failed isolation, invalid bootstrap, or an accepted incorrect rule answer. Once a safety kill is established, persist it and prevent further evaluation dispatch. **Test:** begin with passing ratios, then independently inject failed isolation, bootstrap failure, and a rule error; no positive magnitude or affected gate may survive, and no subsequent call may launch after the kill.

19. BLOCKER A4.7, `usage.py:Certificate`, `load_archived_certificate`, `cache_certified_for_route`. Production certification trusts the certificate’s stated pair and decoder hash without verifying the referenced source envelopes or capture decoder trace. The generic pair predicate also accepts any equal input totals with different cached counts, although A4 authorizes a specific historical certificate and imposes additional requirements on alternatives. **Fix:** distinguish arithmetic pair validity from certificate authority. Verify the authorized archive, its hashes, source mapping, and applicability to the actual frozen route before returning certification. **Test:** remove or alter a source envelope, alter the capture decoder trace, or substitute an unauthorized pair; positive cached usage must become unverified, while valid zero cached usage remains complete.

20. CHANGE A4.7 and A4.11, `score.py:score_run` sensitivity construction. Additive sensitivity changes `cells[*].tokens` but leaves `R_cells` unchanged. Consequently, the reported sensitivity magnitude repeats inclusive accounting even when cache counts are positive. **Fix:** recompute operation attribution and R totals from additive attempt costs before evaluating sensitivity magnitude. **Test:** use unequal cache contributions between A and C that cross a token threshold; inclusive and additive magnitude results must differ appropriately.

21. CHANGE A4.7 and A4.11, `usage.py:decode_codex`, `decode_sonnet`. A missing counter causes an early return before checking contradictions already demonstrated by available counters. For example, cached input greater than input becomes merely incomplete if reasoning is absent. Sonnet negative counters likewise become incomplete. **Fix:** preserve known accounting violations independently of missing information, reporting invalidity alongside incompleteness where necessary. **Test:** combine missing counters with negative values or cached input above input; the accounting failure must remain visible.

22. CHANGE A4.12, `run.py:snapshot_preparation`, `score.py:score_run`, `render_md`, `quota.py`. Require finite, attributable, sufficiently fresh quota readings before dispatch. **Test:** use stale or malformed readings and add preparation entries after initialization; launch must fail safely where appropriate, and the final report must reconcile all categories without double counting physical calls.
