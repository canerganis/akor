# Council build review: OZ map clean replication, round 2

I do not sign commit `c345c4b`. Many round 1 fixes are effective, but recovery can still resend a captured terminal answer, scoring does not fully reconstruct accounting or rule provenance, and interrupted timing can lose completed work. The experiment ledger also deduplicates distinct calls across replacement run directories. P3, P4 and P5 remain launch prerequisites requiring resolution before freeze. This review preserves operation blindness. I checked the supplied diff, operation blind amendment authority and Git metadata. Additional Python probes were blocked by the sandbox, so the new code findings below are static conclusions, not reproduced test results. I made no evaluation calls and changed no files. Paths below are relative to `bench/ozmap_rep/` unless stated otherwise.

1. BLOCKER A4.2, `isolation.py:telemetry_certificate`, `run.py:TelemetryRun.arm`. **Round 1 item 1 is partially closed.** The empty home execution probe improves authentication evidence, and startup instruction filenames now prevent certification. However, a successful execution with `auth.json` plus failure without it does not establish that execution used its credentials exclusively. A credential store lookup indexed by account information from that file could satisfy both observations. The certificate contains no authentication access trace or equivalent pinned implementation evidence. **Fix:** bind certification to metadata establishing the execution route’s authentication source and effective instruction sources. Preserve paths, access types and hashes without token contents. Resolve bundled startup instructions under item 33. **Test:** simulate credential store authentication that requires account metadata from `auth.json`; the current positive and negative observations must not suffice to certify it.

3. BLOCKER A4.2, A4.3 and A4.11, `run.py:recover_inflight`, `CellRun.execute`, `spawn`, `CellRun.after_group`, `score.py:score_run`. **Round 1 item 3 is not fully closed.** Recovery converts every orphan into `interrupted` without inspecting an already persisted capture or parsed call. A crash after capture persistence but before the attempt append can therefore cause a terminal answer, refusal or execution to be resent. Scoring then skips interrupted attempts, leaving their existing captures unjudged. Separately, PID persistence exceptions are suppressed, and a missing PID with an apparently clean home is treated as recoverable even though a child could have started. `execute()` also converts any spawn exception into a retryable failure without establishing child termination. **Fix:** reconcile durable captures and parsed outputs before assigning interruption or retry eligibility. Preserve terminal outcomes. Require established process termination before cleanup, and stop Codex on ambiguous process identity or postspawn exceptions. **Test:** crash between capture, call record and attempt persistence for successful, refused and executed calls. None may be resent. Inject PID journal failure and a communication exception while the child remains alive; recovery must preserve its home and prevent dispatch.

BLOCKER A4.2, `run.py:judge_codex`, `CellRun.worker_probe`, `CellRun.record_features`, `isolation.py:Isolation.propagate`. **Round 1 item 5 is closed for evaluation calls but remains open for local probes.** Evaluation authentication detection now precedes other verdicts, and propagation checks the prepared generation under the lock. However, `worker_probe()` always reconciles with `auth_failure=False`. A probe reporting authentication failure can therefore propagate changed credentials. `record_features()` also accepts a failed command or an empty parsed feature inventory and writes a record whose mere existence satisfies scoring. **Fix:** inspect probe error channels before reconciliation, stop Codex on authentication failure, and require a successful, structurally valid feature inventory before evaluation dispatch. **Test:** return an authentication failure from `features list` or worker `login status` while changing worker authentication. The baseline must remain unchanged and Codex must stop. A failed or empty feature response must prevent evaluation launch.

BLOCKER A4.2, `run.py:CellRun.prepare_call`, `CellRun.secrets`, `CellRun.after_group`, `CellRun.worker_probe`, `redact.py:merge`. **Round 1 item 6 is partially closed.** Ordinary captures are sanitized before persistence, but the prepared credential values are not retained in memory. If the worker refreshes and the baseline is independently reseeded, neither file necessarily retains an old opaque refresh token emitted by the child. Generic JWT and API key patterns do not cover arbitrary refresh tokens. Probe redaction similarly reads the baseline after reconciliation. In addition, `redact.merge()` discards the individual `original_sha256` records. **Fix:** capture credential strings in memory at preparation, combine them with all observed postcall credentials, sanitize before reconciliation can replace their source, and persist separate redaction hash records for each channel. Treat probe disclosures consistently. **Test:** emit the prepared opaque refresh token, refresh the worker, and reseed the baseline before capture processing. No external artifact may contain that token, and the redaction evidence must retain the original capture hash.
