# Astra + Fable review and the joint-plan measurements (2026-10-12)

All live numbers: `claude -p`, pinned model ids, 5 repetitions per cell, fresh records every repetition,
strict validation (a fenced or prose-wrapped reply is invalid, as in the product). Totals are input
(including ~950 fixed CLI tokens) plus billed output (including hidden reasoning).

## Corrections to earlier results

- `--model haiku` resolved to `claude-haiku-4-5`, not Haiku 5.5. Every earlier "small model" result
  (frames losing, effort having no effect, 10-25x hidden reasoning) was about Haiku 4.5.
- The harness stripped Markdown fences that the product rejects. Haiku 5.5 produced no fences.
- The cache-read observation came from byte-identical repeats; in production only the CLI prefix caches.
- The first heterogeneous run had a baseline packet bug (three operations did not name their record);
  fixed and the 0.8 arm rerun.

## Ideas for long workflows (both reviewers, ranked the same at the top)

1. The host runs deterministic operations itself; the model is never called for them.
2. The plan is data: one strong-model call writes the job graph, the host executes it in batches;
   agents do not converse.
3. Reuse validated results (content-addressed memo with dependency invalidation).
4. Direct API instead of the CLI (removes ~950 tokens per call; Codex ~24,500).
5. Effort or thinking routed per operation class, admitted only at 100% measured correctness.
6. Accept per job and retry only failed jobs instead of rejecting a whole 64-job reply.
7. Send only the view of a record that an operation needs.
8. Sampled verification with escalation.

## Progressive cached session (the owner's idea)

Both reviewers: it loses on raw tokens by construction and can win only on billed cost, when calls
stay within the cache lifetime (5 minutes). The killer risk is idle gaps: one cold cache rewrites the
whole session at 1.25x. Fable proposes a variant that keeps the benefit without conversation history:
one append-only cached block (rules, operations, records in first-use order) plus the step's jobs,
no replies kept in context. Astra would allow it as an optional cost mode only with at least 15% lower
cost per successful workflow, no p95 latency regression and no stale-version errors.

## Decision needed

The release gate counts raw tokens. Under that metric caching and the progressive session are worth
nothing; under a billed-cost metric they are worth testing. Both reviewers leave this to the owner.
